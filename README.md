# إبداع سبأ — نظام الصرافة والمحاسبة

واجهة RTL وبداية API محمية لتسجيل الدخول وترحيل القيود المحاسبية. هذه مرحلة تأسيسية؛ لا تعتبر النظام بعدُ نظامًا جاهزًا للإنتاج أو للاستخدام المالي الحقيقي، وما زالت شاشات التشغيل والتقارير وربط البيانات قيد التنفيذ.

## تشغيل المعاينة محليًا

المتطلبات: Node.js 20+ وDocker Compose.

```bash
cp .env.example .env
```

عدّل `.env` قبل التشغيل: غيّر `DATABASE_URL` إلى كلمة المرور المحلية الموجودة في `docker-compose.yml` (`local-dev-password`)، وضع قيمة عشوائية سرية لا تقل عن 32 حرفًا في `SESSION_SECRET`، واختر كلمة مرور مدير لا تقل عن 12 حرفًا. لا ترفع `.env` إلى Git.

ثم شغّل:

```bash
docker compose up -d db
npm install
npx prisma migrate dev --name initial
npm run db:admin
npm run dev
```

افتح http://localhost:3000 ثم سجّل الدخول باسم المستخدم وكلمة المرور المحددين في `.env`. لا توجد بيانات دخول افتراضية ولا بيانات عملاء تجريبية.

## ما يعمل في هذه المرحلة

- تسجيل دخول فعلي بحساب محفوظ في PostgreSQL، كلمة المرور محفوظة بـ bcrypt، وجلسة في Cookie آمنة HttpOnly.
- حماية صفحات التطبيق، ونقطة خروج، وقراءة الحساب الحالي.
- نموذج قاعدة بيانات علائقي للعملات والحسابات والعملاء والصناديق والقيود والسندات وسجل التدقيق.
- API لترحيل قيد محاسبي بعملة واحدة: يتحقق من المبالغ العشرية، الحسابات والعملات النشطة، وتساوي إجمالي المدين والدائن؛ ثم يحفظ القيد وخطوطه وسجل التدقيق في معاملة واحدة.
- ترقيم السندات يتم من قاعدة البيانات تلقائيًا عند الإنشاء.

## ملاحظات محاسبية وأمنية

- أرصدة الحسابات يجب أن تُحسب من خطوط القيود، وليست مخزنة كرصيد قابل للتعديل. لم نضف بعد واجهة/تقرير دفتر الأستاذ وميزان المراجعة.
- القيد متعدد العملات، تحويل العملات، إنشاء السندات وترحيلها، شجرة الحسابات الجاهزة، صلاحيات كل عملية، حماية معدلات تسجيل الدخول، واختبارات تكامل قاعدة البيانات لم تُنجز بعد.
- قبل استخدام أي بيانات مالية حقيقية، يلزم مراجعة محاسبية وأمنية واختبار النسخ الاحتياطي والاستعادة ونشر HTTPS مع إدارة أسرار مناسبة.
